# Notes de version v0.8.0

Date de publication : 2026-09-03

La v0.8.0 vise à ce que l’agent **exécute réellement** : les skills deviennent des ressources gérées au niveau de l’espace, exécution de scripts, fichiers et livrables dans un **sandbox par session** ; **mémoire à long terme** inter-sessions pour retenir préférences et informations que vous avez confirmées. Parsing Office **in-app**, plus GitLab, source Tencent IMA, modèles via **LiteLLM** et plugin **DeepSeek Harness**.

Avant migration depuis v0.7.x : [Notes de mise à niveau](#upgrade-notes). Liste complète : [CHANGELOG](https://github.com/Tencent/WeKnora/blob/main/CHANGELOG.md).

## Sandbox de skills {#skill-sandbox}

Les skills de l’agent tournent dans un sandbox par session : une conversation = un sandbox ; les tâches multi-tours partagent le même workspace (commandes, lecture/écriture/édition de fichiers, pièces jointes, fichiers générés).

<Screenshot
  src="/screenshots/skill-sandbox-chat.png"
  caption="L’agent génère un document Word depuis la KB et prévisualise le fichier à côté du fil" />

- **Trois backends** : Docker (mono-instance ou self-hosted), E2B (cloud ou control plane compatible), CubeSandbox — même protocole distant.
- **Configuration par espace** : image, CPU/RAM, TTL, DNS, modèles et snapshots ; politique réseau par config (deny outbound par défaut, allow/deny lists).
- **Docker désactivé par défaut** : monter `docker.sock` ≈ root sur l’hôte — activer dans « Paramètres système → Sécurité réseau » ou `WEKNORA_SANDBOX_DOCKER_ENABLED=true`.
- **Fichiers produits** : regroupés dans le tiroir artefacts de chaque message ; prévisualisation, téléchargement, notification si nouveaux fichiers.
- **Compression des longues tâches** : compresse l’historique d’appels d’outils sans tronquer/réécrire les fichiers ; préfixe de prompt stable + marqueurs de cache pour Anthropic et API compatibles OpenAI ; consommation de tokens enregistrée par tour.

Voir [Catalogue de skills et sandbox](../03-features/22-skills-sandbox.md) et [Déploiement sandbox](../06-development/04-sandbox-deployment.md).

## Catalogue de skills par espace {#skill-catalog}

Les skills sont des ressources de premier niveau dans l’espace, plus des fichiers à côté du processus serveur.

<Screenshot
  src="/screenshots/skill-catalog.png"
  caption="Catalogue : skills et sandboxes d’installation" />

- **Sources d’installation** : ClawHub, SkillHub / skills.sh, liens GitHub / GitLab, ou ZIP.
- **Installation par sandbox** : snapshot sur la config choisie, progression et journal en direct, arrêt/réinstallation ; désinstallation conserve le paquet dans le répertoire.
- **Consultation et édition en ligne** : fichiers des skills installés dans les paramètres ; l’agent peut utiliser `write_skill_file`, `edit_skill_file` ; `shell_exec` n’exige plus une skill préinstallée.
- **Variables d’environnement** : niveau personnel et espace, injectées à l’exécution, non relues après enregistrement.
- Mention `@` d’une skill ne réduit plus par erreur l’ensemble des skills disponibles.

## Mémoire à long terme inter-sessions {#memory}

Nouvelle mémoire à long terme, indépendante de la mémoire de conversation Neo4j retirée en v0.7.1.

- **Activation optionnelle** : une fois activée dans l’espace, chaque utilisateur peut la désactiver.
- **Catégories** : profil, préférences, faits, tâches, centres d’intérêt — écriture explicite ou extraction automatique en arrière-plan.
- **Confirmation utilisateur** : les inférences automatiques restent en attente jusqu’à confirmation.
- **Usage** : profil et préférences injectés à chaque tour ; faits contextuels par mots-clés ou rappel sémantique ; `search_memory` à la demande ; documents souvent cités pondérés à la recherche.
- Paramètres, entrées, sujets, liens documents, confirm/reject, export et consolidation forcée via `/api/v1/memory/*` — clés API pleine permission uniquement, toujours pour l’appelant.

Voir [Mémoire à long terme](../03-features/23-memory.md) et [API mémoire](../04-api/02-api-memory.md).

## Parsing documentaire et sources {#parsing-and-sources}

- **anydoc in-app** : doc, docx, ppt, pptx et autres formats Office convertibles par anydoc parsés dans l’app Go, sans docreader ; image app liée à anydoc par défaut.
- **XMind** : `.xmind` → plan, indexé comme les autres documents.
- **Étiquetage auto** : après parsing, le modèle de chat choisit parmi les tags existants de la KB (ajout incrémental, pas de nouveaux tags, pas d’écrasement des tags manuels).
- **GitLab et Tencent IMA** : sync de projets GitLab ; notes IMA via OpenAPI avec retry sur erreurs temporaires.
- **Qualité** : cellules fusionnées verticales et texte de table DOCX conservés ; images PDF intégrées plus noires ; échec de crawl web = erreur, pas de page d’erreur indexée.

Voir [Parsing](../03-features/03-document-parsing.md) et [Sources de données](../03-features/10-datasource.md).

## Modèles, recherche et écosystème {#ecosystem}

- **LiteLLM** : fournisseur de premier niveau pour chat, embedding et rerank ; une passerelle vers plusieurs modèles amont.
- **Exa et Metaso** : deux nouveaux fournisseurs de recherche web.
- **Plugin DeepSeek Harness** : [`@wxg-prc-cpg/dsh-weknora`](https://www.npmjs.com/package/@wxg-prc-cpg/dsh-weknora) — outils lecture seule `weknora_search`, `weknora_read_document`, `weknora_ask`, `weknora_list_knowledge_bases`. Voir [DeepSeek Harness](../05-clients/08-deepseek-harness.md).

## Expérience de conversation {#chat}

- Fil long : table des questions pour navigation ; séparateurs temporels entre messages.
- `shell_exec` en carte « commande + sortie » ; cartes outil avec liste de fichiers sandbox et nom de skill.
- Diagrammes Mermaid stables pendant le streaming (plus de clignotement).

## Comptes et sécurité {#security}

- **OIDC** : signature ID Token via JWKS ; `/auth/oidc/start` pour connexion directe.
- **Mot de passe complexe optionnel** : inscription, changement et reset admin exigent majuscules, minuscules, chiffres et caractères spéciaux (`WEKNORA_AUTH_COMPLEX_PASSWORD_ENABLED` ou paramètres système).
- **Création d’utilisateurs par l’admin** : depuis la console, sans lien d’invitation.
- **Invitations** : auto-accept si utilisateur déjà inscrit ; mode invitation seule : lien partagé → connexion puis espace.
- **Sandbox** : exécution Docker en utilisateur sandbox (uid 1000), symlinks d’évasion désactivés, zombies des exécutions annulées nettoyés.

## Notes de mise à niveau {#upgrade-notes}

| Changement | Action |
| --- | --- |
| Backend sandbox Local (processus hôte) supprimé | Recréer avec Docker (activation manuelle), E2B ou Cube |
| Backend Docker sandbox désactivé par défaut | « Paramètres système → Sécurité réseau » ou `WEKNORA_SANDBOX_DOCKER_ENABLED=true` |
| Mot de passe complexe : requêtes non conformes rejetées | Informer les utilisateurs avant activation |

Migrations DB : PostgreSQL `000080`–`000090`, SQLite `000003`–`000012`. Backend Docker : `appuser` dans le conteneur app doit appartenir au groupe de `docker.sock`.

## Autres améliorations et correctifs {#other-changes}

- **Recherche** : MMR incrémental ; hybrid search respecte `resource_urls=public` ; `MatchCount=0` ne tronque plus tout ; images supprimées exclues.
- **IM** : Feishu long polling derrière reverse proxy ; cartes stream avec progression en mode complet ; compatibilité WeCom, DingTalk, Yunzhijia ; pièces jointes en Q&R IM.
- **Espace et documents** : dernier espace mémorisé ; changement de mot de passe dans les paramètres personnels ; upload par glisser-déposer de répertoires conserve l’arborescence ; résumé document éditable ; liste de chunks paginée.
- **Capacités de déploiement** : modules non enregistrés masqués dans menus et paramètres (`GET /system/capabilities`) ; Lite n’affiche plus les fonctions absentes.
- **Correctifs** : paramètres système à haut risque lisent la dernière valeur ; cartes Feishu stream ne restent plus bloquées ; suppression de modèle référencé avec détail ; KB partagée : nombre de documents dans le contexte agent ≠ 0 ; noms/descriptions des agents intégrés suivent la langue UI.
