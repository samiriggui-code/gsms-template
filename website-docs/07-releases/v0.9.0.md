# Notes de version v0.9.0

Date de publication : 2026-10-29

v0.9.0 introduit l’**assistant de travail WeKnora** : réponses sur versions, fonctionnalités et configuration WeKnora, contextualisées à la page, avec création d’agents, tâches planifiées, organisation des connaissances et réglages — le tout avec votre identité. Les travaux complexes peuvent être répartis entre plusieurs agents. Vous choisissez lecture seule, confirmation avant modification ou exécution automatique, avec traitement des opérations soumises à approbation. Cette version améliore aussi la réutilisation sandbox, l’analyse documentaire, la synchro des sources et la recherche.

Avant de monter depuis v0.8.3, lire [Consignes de mise à niveau](#upgrade-notes). Liste complète : [CHANGELOG](https://github.com/Tencent/WeKnora/blob/main/CHANGELOG.md).

## Assistant WeKnora : Q&R produit et tâches concrètes {#assistant}

Nouvelle entrée à côté du logo (coin supérieur gauche) ouvre l’assistant WeKnora à droite. Questions sur mises à jour, usage, configuration et dépannage ; ou, depuis un agent, une base, un document ou des paramètres, création d’agent, planification, organisation ou réglages. Exécution avec l’identité et les permissions de l’utilisateur courant.

Une guide unique après upgrade pointe le bouton ; les nouveaux utilisateurs le voient aussi dans l’accueil.

<Screenshot src="/screenshots/assistant-release-guide.png" caption="Demander les nouveautés v0.9.0 et consulter la doc produit" />

<Screenshot src="/screenshots/assistant-overview.png" caption="Traiter une tâche concrète en s’appuyant sur la base courante" />

- **Q&R produit** : documentation produit, versions, usage, configuration, dépannage.
- **Identité utilisateur** : périmètre d’accès et de modification selon vos droits.
- **Création et configuration** : agents, modèles, bases, automatisations pour travail répétitif.
- **Contexte de page** : ressource affichée, ouverture de pages et aide à la saisie.
- **Historique séparé** : conversations assistant distinctes pour reprendre le fil.

La page courante aide le contexte sans restreindre automatiquement toute la recherche ; `@` précise les sources du tour. Voir [Assistant WeKnora](../03-features/26-weknora-assistant.md).

## Collaboration multi-agents {#collaboration}

Découper recherche, analyse ou synthèse en sous-tâches indépendantes confiées à plusieurs agents. La tâche principale agrège les résultats ; statut et sorties des sous-tâches sont suivis ; approbations en attente reprennent sous votre contrôle.

<Screenshot src="/screenshots/agent-collaboration.png" caption="Collaboration : progression et résultats par sous-tâche" />

Agents collaborateurs ad hoc ou réutilisation d’agents « raisonnement intelligent » de l’espace. Sous-tâches avec sessions dédiées — pas de copie automatique de tout l’historique parent ni des pièces jointes, pas d’élargissement des permissions. Voir [Collaboration](../03-features/26-weknora-assistant.md#collaboration).

## Automatisations {#automations}

Actualités quotidiennes, synthèses périodiques, contrôle d’état des bases : tâches enregistrées avec exécution unique ou planification Cron (fuseau, modèle, mode de session, notifications).

Configuration en langage naturel via l’assistant ou formulaire pas à pas sur la page Automatisations.

<Screenshot src="/screenshots/automation-conversation.png" caption="Configuration en une phrase : l’assistant prépare le plan à valider" />

<Screenshot src="/screenshots/automation-setup.png" caption="Configuration manuelle : récurrence, heure, fuseau, prochaine exécution" />

Exécution par l’assistant WeKnora au nom du créateur. Pause et notification si approbation requise ; historique complet des runs ; pause, exécution manuelle ou annulation ponctuelle. Autorisations long terme limitées à la tâche, l’action et les ressources, toujours soumises aux contrôles de droits. Voir [Automatisations](../03-features/27-automations.md).

## Permissions d’exécution et approbations {#permissions}

Trois modes : **lecture seule**, **confirmation avant modification**, **exécution automatique** — distinction lecture, écriture courante et opérations destructives. En automatique, suppressions et outils à approbation forcée restent confirmés ; en lecture seule, pas de contournement des écritures via approbation.

<Screenshot src="/screenshots/assistant-permissions.png" caption="Choisir la permission de session et vérifier le périmètre à l’approbation" />

Approbations et runs reprise persistants après rafraîchissement. Autorisations de session et d’automatisation ont chacune leur périmètre ; révocation et changements de droits restent effectifs. Voir [Permissions et approbations](../03-features/28-agent-permissions.md).

## Sandbox et tâches de fond {#sandbox}

- **Réutilisation par utilisateur** : option explicite côté déploiement — même machine pour un utilisateur et une config, répertoires de travail distincts par session ; défaut = allocation par session.
- **Shell de fond** : commandes longues en tâche de fond avec sortie, attente ou annulation — sans `nohup` manuel.
- **Mise à jour de compétences** : en allocation par session, appliquer au tour suivant ou à une nouvelle session ; en réutilisation utilisateur, pas de rebuild automatique de la machine en cours d’usage.
- **Exécution Lite locale** : répertoire de session par défaut sous `~/.weknora/sessions` ; approbations plus explicites pour suppressions locales et extension d’accès sandbox.

Les répertoires sur machine partagée ne sont pas isolés au niveau OS. Conditions, comportement des sessions existantes et rollback : [Compétences et sandbox](../03-features/22-skills-sandbox.md#user-sandbox).

## Sources, analyse et recherche {#knowledge}

- **Feishu / Lark** : parsing blocks par défaut (tableaux, images, pièces jointes, arborescence) ; mode configurable dans la source.
- **DingTalk / Confluence** : structure de dossiers DingTalk ; Confluence Server/DC avec PAT.
- **Images** : pipeline configurable, prétraitement OCR par base.
- **Tableaux et web** : Excel en pourcentages affichés (option) ; extraction de corps HTML (option), comportement par défaut inchangé.
- **Recherche** : réglages RRF, recherche MCP par périmètre documentaire, API graphe JSON ; corrections isolation multi-dimension et erreurs de retrieval.
- **FAQ** : modes d’expansion de liste pour navigation et maintenance.

Voir [Analyse documentaire](../03-features/03-document-parsing.md), [Sources](../03-features/10-datasource.md), [Feishu Drive](../03-features/24-feishu-drive.md), [Moteurs de recherche](../03-features/05-retrieval-engines.md).

## Autres améliorations et correctifs {#other-changes}

- **Modèles et streaming** : meilleure compatibilité SSE, lignes multiples, contenu de raisonnement et refus — moins de pertes sur flux anormaux.
- **Défauts d’espace** : « Paramètres → Défauts » pour modèles chat, tâches auxiliaires, embedding, rerank, vision, ASR et recherche web ; choix explicites dans agents/bases/tâches priment. Voir [Défauts d’espace](../03-features/06-models.md#workspace-defaults).
- **Outils et complétion** : détection/validation appels outils DSML (OpenAI compatible) ; raison de fin Ollama conservée ; erreur si flux MCP sans événement de fin ; réponse finale sans thinking supplémentaire ; limite taille réponses vision WeKnoraCloud.
- **Traitement documentaire** : Office, PDF, EPUB, CSV, images ; limites mémoire sur fichiers aberrants ; annulation, retry et retours d’échec.
- **Contenu et recherche** : Markdown assistant préserve indentation/sauts ; Lite ignore BM25 si requête tokenisée vide ; correction métriques BLEU/NDCG.
- **Sync et accès** : curseurs, rapprochement suppressions, téléchargements pièces jointes, contrôles de périmètre ressource.
- **Session et UI** : pièces jointes, résultats d’outils, collaboration, tâches de fond ; assistant selon la page.
- **Attente d’approbation** : état persistant avec échéance si applicable — plus de faux compte à rebours utilisateur pour attentes courtes.
- **IM, CLI, SDK** : mentions de groupe, messages canal, compatibilité CLI/clients.
- **Site** : doc assistant, automatisations, permissions ; mises à jour configuration, API, architecture, migrations.

## Consignes de mise à niveau {#upgrade-notes}

### Avant la montée

1. Sauvegarder base, stockage fichiers et configuration ; fichiers sandbox à conserver séparément si besoin.
2. Vérifier images et prérequis de migration. Après v0.8.3 : PostgreSQL `000119–000134`, SQLite `000037–000051` (approbations, assistant, collaboration, automatisations, allocation sandbox, défauts d’espace).
3. Plafonds de permission assistant vs agents classiques, approbations MCP, périmètres d’automatisation.

### Données et configuration

- **`tenants.default_settings`** : modèles par défaut d’espace ; repli déploiement si absent ; tâches auxiliaires suivent le défaut chat si vide. Ne remplace pas en masse les choix déjà enregistrés dans bases/agents.
- **Resync Feishu/Lark** : migration planifie une resynchronisation — surveiller charge, parsing et modèles. Nouvelles sources : blocks par défaut ; mode export explicite conservé.
- **Nettoyage chunks image vides** : migration supprime anciens captions/OCR/vecteurs vides — pas les documents ni fichiers sources.
- **Réutilisation sandbox** : `WEKNORA_SANDBOX_USER_ALLOCATION=enabled` exige Redis ; monter tous les réplicas app avant activation ; pas de migration forcée des bindings ; pas de downgrade vers version sans allocation partagée.
- **Format de logs** : `WEKNORA_LOG_FORMAT` prioritaire ; sinon `LOG_FORMAT` ; template non vide doit contenir `%msg` ; valeur vide explicite = pas de format custom.
- **Quota** : `WEKNORA_TENANT_DEFAULT_STORAGE_QUOTA_MB` pour nouveaux espaces uniquement.
- **Options d’analyse** : OCR, extraction HTML, Excel pourcentages — activation manuelle, pas de reparse global automatique.
- **Timeouts** : MinerU Cloud 30 min par lot par défaut ; capture web 3 min partagés — aligner proxy, appelants et serveur.

### Images et validation

Après publication tag et images, `WEKNORA_VERSION=0.9.0` dans `.env`, mettre à jour les manifests et :

```bash
docker compose --profile full pull --policy always
docker compose --profile full up -d
docker compose ps
```

Seul `up -d` peut réutiliser d’anciennes images locales. Vérifier migrations, version UI, échantillon parsing/recherche, assistant (approbations, notifications, fichiers sandbox) sur tâches à faible risque. Déploiement : [Installation](../01-getting-started/02-installation.md). Depuis versions antérieures : aussi [v0.8.3](v0.8.3.md#upgrade-notes) et [v0.8.2](v0.8.2.md#upgrade-notes).
